# RBAC role and scope rename: clean break, no back-compat

The existing role ladder (`student < staff < manager < scheduler < admin`) named `manager` as location-scoped and `scheduler` as department-scoped — backwards from how a reader would guess, since "scheduler" sounds like a function, not a rank, and "manager" doesn't say what it manages. Firming up RBAC around six named roles (Student Worker, Staff, Team Manager, Department Manager, Admin) meant renaming both the roles and the scope entities under them (`locations`→`departments`, `departments`→`teams`) so role names and DB vocabulary agree.

We chose a full clean break over a compatibility shim: rename the role strings, table names, and columns everywhere in one migration, rather than keeping old identifiers and only relabeling the UI. This is a bigger diff up front, but avoids a permanent split where role names (`department_manager`) and schema names (`location_id`) point at each other backwards — the exact confusion the rename was meant to fix. Considered keeping identifiers untouched and relabeling only in the UI/docs; rejected because it would leave the mismatch in the codebase indefinitely for a greenfield project with no external consumers depending on the old names yet.
